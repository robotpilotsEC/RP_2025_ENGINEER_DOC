# Udev权限

## 重点！！！！

在 `launch.json`文件中配置完 `openocd`点击开始调试调试你可能会遇到以下报错
>Error: unable to open CMSIS-DAP device 0xef1a:0x74e5 （这个id每个daplink都不一样）
>Error: unable to find a matching CMSIS-DAP device

这是因为你直接点击开始调试是以用户权限启动，`openocd`对usb设备的读写没有权限（daplink就是一种usb设备）
因此，你要么配置为管理员启动调试，要么手动写一个 `plugdev`用户组

## 检查你的权限
~~~
ls -l /dev/hidraw*
~~~
如果你的终端上显示以下信息，说明你所有的设备都需要**root**才能访问
~~~
sassinak@sassinak:~$ ls -l /dev/hidraw*
crw------- 1 root root 241, 0  8月 11 00:38 /dev/hidraw0
crw------- 1 root root 241, 2  8月 11 00:38 /dev/hidraw2
crw------- 1 root root 241, 3  8月 11 00:38 /dev/hidraw3
crw------- 1 root root 241, 4  8月 11 00:38 /dev/hidraw4
crw------- 1 root root 241, 5  8月 11 00:38 /dev/hidraw5
crw------- 1 root root 241, 6  8月 11 00:38 /dev/hidraw6
crw------- 1 root root 241, 7  8月 11 00:38 /dev/hidraw7
~~~

那就说明你需要解决一下你的权限问题了

## 添加 `plugdev`
1.获取你daplink的 `idproduct`
~~~
lsusb	#找到cmsis-adp，ID：ef1a后就是你的 `idproduct`
#或者
lsusb | grep ef1a	#也可以找到id
~~~

2. 添加一个 `plugdev`
~~~
#创建一个规则文件
sudo nano /etc/udev/rules.d/60-cmsis-dap-horco.rules	
#往文件内写入以下内容
SUBSYSTEM=="usb", ATTRS{idVendor}=="ef1a", ATTRS{idProduct}=="74e5", MODE="0666", GROUP="plugdev"
KERNEL=="hidraw*", ATTRS{idVendor}=="ef1a", ATTRS{idProduct}=="74e5", MODE="0666", GROUP="plugdev"
#保存并退出

#重新加载
sudo udevadm control --reload-rules
sudo udevadm trigger
#重启并插拔daplink
~~~

3. 再次检查
~~~
ls -l /dev/hidraw*

#此时你应该能看到：
sassinak@sassinak:~$ ls -l /dev/hidraw*
crw------- 1 root root    241, 0  8月 11 00:38 /dev/hidraw0
crw-rw-rw- 1 root plugdev 241, 1  8月 11 21:02 /dev/hidraw1
crw------- 1 root root    241, 2  8月 11 00:38 /dev/hidraw2
crw------- 1 root root    241, 3  8月 11 00:38 /dev/hidraw3
crw------- 1 root root    241, 4  8月 11 00:38 /dev/hidraw4
crw------- 1 root root    241, 5  8月 11 00:38 /dev/hidraw5
crw------- 1 root root    241, 6  8月 11 00:38 /dev/hidraw6
crw------- 1 root root    241, 7  8月 11 00:38 /dev/hidraw7
~~~
