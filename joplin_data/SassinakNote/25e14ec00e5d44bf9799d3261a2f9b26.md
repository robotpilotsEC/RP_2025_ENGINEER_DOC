用设备树配置硬件信息

# 用设备树配置硬件信息
**底层的dts文件通常由芯片厂商和板卡厂商就写好了，作为用户，我们需要的是写 `overlay` 或者对底层做维护和小修小改**
 
***
## 基本结构
1. 根节点
~~~
/ {
	/*属性，子节点*/
}
~~~
`/`:表示根节点
2. 子节点，待变各种硬件组件，包括CPU，内存，GPIO
~~~
CPU@{
	/*属性*/
}
~~~
3. 节点属性，以**键值对**的形式存在，描述节点的特定信息，如寄存器地址，时钟
4. `@`后如果有地址必须和第一个寄存器地址相同，如果没有，必须**省略**

## 实例分析
~~~
/dts-v1/； #这是设备树的版本，必须写在第一行

/include/ "mt7628an.dtsi" //引用的头文件，用于描述一个soc的通用信息（比如cpu、soc、中断控制等等）

/ {
    // compatible属性定义了设备的兼容性，通常包含特定于平台或板卡的字符串
    compatible = "mediatek,mt7628an-eval-board", "mediatek,mt7628an-soc";
    // model属性定义了设备的型号，用于标识硬件平台
    model = "Mediatek MT7628AN evaluation board";

    // chosen节点用于定义一些系统级的配置选项
    chosen {
            // bootargs属性定义了内核启动时的参数，例如串口控制台的配置
            bootargs = "console=ttyS0,115200";
    };

    // memory节点定义了内存的配置
    memory@0 {
        // device_type属性标识了该节点代表的硬件类型，这里是内存
        device_type = "memory";
        // reg属性定义了内存的起始地址和大小
        // 第一个值是内存的起始地址，第二个值是内存的大小
        // 下面的值被注释掉，用于展示不同的配置选项，当前启用的是128MB的RAM配置
        // reg = <0x0 0x10000000>; //256MB RAM
        reg = <0x0 0x8000000>; //128MB RAM
        // reg = <0x0 0x4000000>; //64MB RAM
    };

    //pinctrl的节点，它负责配置处理器的引脚控制（pin control）设置。
    //在嵌入式系统中，pinctrl是管理处理器引脚功能的一种机制。
    pinctrl {
        // state_default：标签，用于定义一组默认的引脚配置
        state_default: pinctrl0 {
            // 以下节点定义了不同的LED相关的引脚组及其功能
            p0_led { //引脚名
                ralink,group = "p0_led_an"; //引脚组
                ralink,function = "ephy"; //引脚功能
            };
            p1_led { 
                ralink,group = "p1_led_an";
                ralink,function = "ephy";
            };
            p2_led {
                ralink,group = "p2_led_an";
                ralink,function = "ephy";
            };
            p3_led {
                ralink,group = "p3_led_an";
                ralink,function = "gpio";
            };
            p4_led {
                ralink,group = "p4_led_an";
                ralink,function = "gpio";
            };
            // 其余的LED配置与上述类似，指定不同的引脚组及其功能
            spis {
                ralink,group = "spis";
                ralink,function = "pwm_uart2";
            };
            pwm1 {
                    ralink,group = "pwm1";
                    ralink,function = "gpio";
            };
            pwm0 {
                    ralink,group = "pwm0";
                    ralink,function = "gpio";
            };
            refclk {
                ralink,group = "refclk";
                ralink,function = "gpio";
            };
            gpio_0 {
                ralink,group = "gpio";
                ralink,function = "gpio";
            };
            i2s {
                    ralink,group = "i2s";
                    ralink,function = "i2s";
            };
        };
        // 定义uart2引脚的特定设置
        uart2_pins: uart2 {
            uart2 {
                ralink,group = "uart2";
                    ralink,function = "pwm";
                };
        };

    };
    // Palmbus是Mediatek SoC的一个主总线，此处指定了总线的基地址
    palmbus@10000000 {
        i2c@900 {
                status = "okay"; // 启用位于地址0x900的I2C控制器
        };

        spi@b00 {
            status = "okay"; // 启用位于地址0xb00的SPI控制器

            m25p80@0 {
                #address-cells = <1>; // SPI设备树节点的寻址信息，定义了地址单元的数量
                #size-cells = <1>; // SPI设备树节点的大小信息，定义了大小单元的数量
                compatible = "en25q64"; // 指定SPI闪存芯片的型号为en25q64
                reg = <0 0>; // 指定设备在SPI总线上的芯片选择（chip select）编号
                linux,modalias = "w25q64", "w25q128", "w25q256"; // 指定该设备的其他可能兼容型号
                spi-max-frequency = <10000000>; // SPI通信的最大频率，单位为Hz
                m25p,chunked-io = <32>; // 定义了分块I/O操作的大小，这里是32字节

                // 定义了不同的SPI闪存分区
                partition@0 {
                    label = "u-boot"; // 分区名
                    reg = <0x0 0x30000>; // 分区的起始地址和大小（这里是192KB）
                    read-only; // 分区是只读的
                };

                // u-boot环境变量分区
                partition@30000 {
                    label = "u-boot-env";
                    reg = <0x30000 0x10000>; // 分区的起始地址和大小（这里是64KB）
                    read-only;
                };

                factory: partition@40000 {
                    label = "factory";
                    reg = <0x40000 0x10000>; // 分区的起始地址和大小（这里是64KB）
                    read-only;
                };

                // 固件分区
                partition@50000 {
                    label = "firmware";
                    // 不同的注释分区大小对应不同大小的闪存
                    reg = <0x50000 0xfb0000>; // 分区的起始地址和大小（这里是16MB - 320KB）
                };
            };
        };

        // 启用两个UART（通用异步收发传输器）设备
        uart1@d00 {
                status = "okay"; // 启用位于地址0xd00的UART1
        };

        uart2@e00 {
                status = "okay"; // 启用位于地址0xe00的UART2
        };
    };

    // SDHC（Secure Digital Host Controller）配置
    sdhci@10130000 {
        status = "okay"; // 启用SD卡控制器
        mediatek,cd-low; // Mediatek特有的属性，可能表示卡检测（Card Detect）的极性
    };

    // 以太网控制器配置
    ethernet@10100000 {
        mtd-mac-address = <&factory 0x28>; // 从工厂设置分区中指定偏移读取MAC地址
    };

    // GPIO控制的LED配置
    gpio-leds {
        compatible = "gpio-leds"; // 指明兼容的设备类型是GPIO控制的LED

        // 定义系统状态LED
        system {
                label = "mediatek:green:system"; // LED标签
                gpios = <&gpio1 5 1>; // 指定GPIO端口和引脚编号
                default-state = "off"; // 默认状态为关闭
        };

        // 定义Wi-Fi状态LED
        wifi {
                label = "mediatek:green:wifi"; // LED标签
                gpios = <&gpio1 12 1>; // 指定GPIO端口和引脚编号
                default-state = "off"; // 默认状态为关闭
        };
    };

    // GPIO按键配置，采用轮询方式
    gpio-keys-polled {
        compatible = "gpio-keys-polled"; // 指明兼容的设备类型是GPIO按键
        #address-cells = <1>;
        #size-cells = <0>;
        poll-interval = <20>; // 定义按键扫描的间隔时间，单位为毫秒

        // 定义一个GPIO按键
        button_1 {
                label = "button_1"; // 按键标签
                gpios = <&gpio1 6 0>; // 指定GPIO端口和引脚编号
                linux,code = <0x101>; // 按键对应的Linux输入子系统的键值代码
        };
    };  
};
~~~

### 常见的地址属性：
1. `#adress-cells`地址字段的长度（32位字为单位）
2. `#size-cells`大小字段的长度
3. `reg`内存映射，包括起始地址和范围
4. **`range`**描述PCI地址到物理内存地址的映射
~~~
ranges = <
            0x02000000 0 0x00000000 0x20000000 0 0x10000000 /* pci memory */
            0x01000000 0 0x00000000 0x10160000 0 0x00010000 /* io space */
        >;
~~~
1. `0x02000000 0 0x00000000 0x20000000 0 0x10000000`
	- 这个条目描述了**PCI内存空间到物理内存的映射**。
	- `0x02000000`是PCI地址空间的一个标识，通常对应于该空间类型（例如内存空间）。
	- 接下来的 `0` 是PCI总线上的地址（通常为0，表示这是起始地址）。
	- `0x00000000` 是转换后的物理地址的起始点。
	- `0x20000000` 是物理地址空间的大小。
	- 最后的 `0` 和 `0x10000000` 表明这个映射的大小是 0x10000000 字节（256MB）。
2. `0x01000000 0 0x00000000 0x10160000 0 0x00010000`

	- 这个条目描述了**PCI I/O空间到物理内存的映射**。
	- `0x01000000` 标记了这是I/O空间的映射。
	- 同样地，第二个 `0` 表示PCI I/O空间的开始地址。
	- `0x10160000` 是物理地址空间中对应的起始地址。
	- 最后的 `0` 和 `0x00010000` 表示这个映射的大小是 0x00010000 字节（64KB）。

5. `@`后跟数字，通常表示设备在**父总线**或者**父节点**内存映射中的基础地址

### 引脚配置
通常引脚可配置的属性是在内核源码中就被定义好的，要根据不同的芯片编写
1. 指定引脚所属的组名
2. 指定引脚组的功能

### 标签
标签用来表示特定的节点或者属性。同时方便重用和覆盖
>lable :
~~~
factory: partition@40000 {
label = "factory";
reg = <0x40000 0x10000>; // 分区的起始地址和大小（这里是64KB）
read-only;
};
~~~
引用语法：`<&lable (偏移地址)>`  

### 中断属性
~~~
/ {
    compatible = "acme,coyotes-revenge";
    #address-cells = <1>;
    #size-cells = <1>;
    interrupt-parent = <&intc>;

    cpus {
        #address-cells = <1>;
        #size-cells = <0>;
        cpu@0 {
            compatible = "arm,cortex-a9";
            reg = <0>;
        };
        cpu@1 {
            compatible = "arm,cortex-a9";
            reg = <1>;
        };
    };

    serial@101f0000 {
        compatible = "arm,pl011";
        reg = <0x101f0000 0x1000 >;
        interrupts = < 1 0 >;
    };

	intc: interrupt-controller@10140000 {
	        compatible = "arm,pl190";
	        reg = <0x10140000 0x1000 >;
	        interrupt-controller;
	        #interrupt-cells = <2>;
	    };
	};
~~~
- `interrupt-controller`：声明一个节点是接收中断信号的设备，也就是中断控制器
- `#interrupt-cells`：`interrupt-controller`节点下的一个属性，表明中断标识符用多少个单元表示
- `interrupt-parent`：设备节点中的一个属性，选择哪个中断控制器
- `interrupts`：设备节点的一个属性，中断标识符列表，其单元个数取决于 `#interrupt-cells`
