# Kconfig启动
## 在zephyr项目中，Kconfig的导入顺序
### 1. 在**项目的应用层**中，常会在cmake中导入zephyr的模块。
~~~
# import zephyr library
find_package(Zephyr REQUIRED HINTS $ENV{ZEPHYR_BASE})
~~~
- 这里指明了从 `$ENV{ZEPHYR_BASE}`去找zephyr模块

### 2. 事实上，这个命令会**间接调用**`zephyr`模块中的 `boilerplate.cmake`。
> zephyr/cmake/app/boilerplate.cmake

一样的，这个文件也是指明了zephyr模块所在的位置。

### 3.关键在于 `kconfig.cmake`
>zephyr/cmake/modules/kconfig.cmake

这个文件主要工作
- **发现 `kconfig`的入口文件**、
- **自动收集文件依赖**，即各种 `kconfig`文件
- 校验
- **通过 `execute_process` 调用 Python 脚本 `kconfig.py`**: 生成 .`config `和`autoconf.h`。
~~~
execute_process(
  COMMAND ${CMAKE_COMMAND} -E env
  ${COMMON_KCONFIG_ENV_SETTINGS}
  SHIELD_AS_LIST=${SHIELD_AS_LIST_ESCAPED_COMMAND}
  ${PYTHON_EXECUTABLE}
  ${ZEPHYR_BASE}/scripts/kconfig/kconfig.py    # 这个是关键
  --zephyr-base=${ZEPHYR_BASE}
  ${input_configs_flags}
  ${KCONFIG_ROOT}  # 这个就是Kconfig顶层目录
  ${DOTCONFIG}
  ${AUTOCONF_H}
  ${PARSED_KCONFIG_SOURCES_TXT}
  ${input_configs}
  WORKING_DIRECTORY ${APPLICATION_SOURCE_DIR}
  # The working directory is set to the app dir such that the user
  # can use relative paths in CONF_FILE, e.g. CONF_FILE=nrf5.conf
  RESULT_VARIABLE ret
  )
~~~
