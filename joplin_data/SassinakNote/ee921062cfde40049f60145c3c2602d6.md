 零，breeze项目结构示例

## 工作空间
~~~
breeze-workspace            工作区，用于隔离开发环境 (如Python的venv)
    |
    |-  breeze              Breeze主清单仓库，拥有额外添加的主板移植以及驱动程序等
    |
    |-  breeze-sdk          SDK目录，主要为Zephyr及其附属模块
    |       | - zephyr      Zephyr-RTOS主仓库
    |       | - modules     Zephyr子模块仓库存放目录
    |
    |-  breeze-app          APP目录，用户进行开发时存放相关仓库的位置
    |       | - app1        用户app1仓库
    |       | - app2        用户app2仓库
    |       | - ...         更多用户app仓库
~~~
- breeze 清单仓库：主要包括了依赖关系，配置参数，部署说明

## 项目更新和初始化
- 使用`west`工具初始化和更新一个`Zephyr`项目，初始化时,`west`会去找 `west.yml`文件。
~~~
manifest:

  defaults:
    remote: robotpilots

  remotes:
    - name: robotpilots
      url-base: https://github.com/RobotPilots-SZU
    - name: upstream
      url-base: https://github.com/zephyrproject-rtos

  projects:
    - name: breeze-app-template
      revision: main
      path: breeze-app/breeze-app-template
    - name: zephyr
      remote: upstream
      revision: main
      path: zephyr
      import:
        path-prefix: breeze-sdk
        # By using name-allowlist we can clone only the modules that are
        # strictly needed by the application.
        name-allowlist:
          - cmsis
          - cmsis_6
          - cmsis-nn
          - cmsis-dsp
          - segger
          - hal_st
          - hal_stm32

  self:
    path: breeze
    import: submanifests  # 这里设置了递归导入 submanifests的配置文件
~~~
可以看到，学长已经精简了所需要同步的模块，如果是在官方自己安装默认配置的Zephyr工程，`module`文件夹内是有很多不必要的工具的。
