# 什么会变成Kconfig选项
- `Symbol`：在 `Kconfig` 文件里，一个 `symbol` 就是一个配置项，比如 `CONFIG_USB_SUPPORT`。
- `Prompt`：如果 `symbol` 定义时有 `prompt`（比如 `bool "Enable USB support"`），那么它会在 `menuconfig` 或 `guiconfig` 的界面里显示，用户可以直接配置它。

**示例**
~~~
config USB_SUPPORT
    bool "Enable USB support"
~~~
- 这里 `USB_SUPPORT` 有 `prompt`，可以在 `menuconfig` 里直接勾选或取消

## 没有 `Prompt` 的 `Symbol`
- 没有提示的符号（隐藏/不可见 `Symbol`）：只被 `Kconfig` 用于逻辑推导
- 常用于**中间变量**或某些功能的**自动判定**，减少用户需要配置的内容
- 不能直接被用户配置

**示例**
~~~
config HAS_USB_DRIVER
    bool
    default y if USB_SUPPORT && DRIVERS_ENABLED
    default n
~~~

## 有 `Prompt` 但“不可见”：依赖不满足时的隐藏
- 有 `prompt` 的 `symbol` 也可能是不可见的——如果它的依赖条件没有满足，它就不会显示在配置界面里。

**示例**
~~~
config ADVANCED_FEATURE
    bool "Enable advanced feature"
    depends on EXPERT_MODE
~~~
- 只有当 `EXPERT_MODE` 为 y 时，`ADVANCED_FEATURE` 才会在界面里出现，否则它是不可见的
