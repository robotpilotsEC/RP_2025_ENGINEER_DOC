# Udev

## 前言
Udev负责在**系统启动**时，**热插拔事件**发生时创建和管理设备节点。
定制Udev行为包括: **更改设备名称**，**权限和所有者**，**执行特定的脚本**。

- Udev属于**用户空间部分**，依赖内核提供的设备信息，存放在 `/etc/udev/rules.d/`
- Udev通常是简单的键值对语法、

***
## Udev规则语法
一个基本的Udev文件：
~~~
ACTION=="add", SUBSYSTEM=="usb", DRIVER=="usb-storage", RUN+="/bin/sh -c 'echo USB storage added > /dev/tty'"
~~~
- `ACTION=="add"`:匹配设备添加事件 
- `SUBSYSTEM=="usb"`:匹配 USB 子系统的设备。
- `DRIVER=="usb-storage"`: 匹配驱动名为 usb-storage 的设备。
`RUN+="/bin/sh -c 'echo USB storage added > /dev/tty'"`: 当规则匹配时，执行这个命令。

## 键值对语法
- `ACTION`: 设备事件类型，如 `add`、`remove` 等。
- `SUBSYSTEM`: 设备的子系统名称。
- `DRIVER`: 设备的驱动名称。
- `DEVNAME`: 设备的文件名。
- `SYMLINK`: 创建到设备文件的符号链接。
- `OWNER`: 设备文件的所有者。
- `GROUP`: 设备文件所属的组。
- `MODE`: 设备文件的权限模式。

每个键后面都跟着一个等号和一个期望的值，用引号括起来。可以使用 `==` 来表示**精确匹配**，或者`:=` 来**设置一个值**,`+=` 来**追加一个值**。

## 执行动作
前面的语法执行的是对设备的匹配和赋值，在后面还可以**对匹配的设备执行操作**
- `RUN`: 执行一个命令。
- `CREATE`: 创建一个设备节点。
- `SYMLINK`: 创建一个到设备节点的符号链接。
- `OWNER`, `GROUP`, `MODE`: 设置设备节点的所有者、组别和权限。

***
## 高级特性
1. 复杂设备匹配
~~~
# /etc/udev/rules.d/99-complex-match.rules
ACTION=="add", SUBSYSTEM=="usb", DRIVER=="usb", ATTR{idProduct}=="1234", ATTR{idVendor}=="5678", ATTR{interface}=="00", RUN+="/bin/sh -c 'echo Complex match for USB device > /dev/tty'"
~~~
在这个规则中，我们使用了 `ATTR` 键来访问设备的属性，如 `idProduct` 和 `idVendor`，它们分别代表**产品的 ID** 和**制造商的 ID**。

2. 允许使用 `AND`和 `OR`逻辑组合多个条件
~~~
# /etc/udev/rules.d/99-combined-rules.rules
ACTION=="add", SUBSYSTEM=="usb", DRIVER=="usb-storage", (ATTR{idProduct}=="1234" AND ATTR{idVendor}=="5678"), RUN+="/bin/sh -c 'echo Combined rule matched > /dev/tty'"
~~~

3. 使用`udevadm`调试
`udevadm`允许我们查看设备属性，监视设备事件，测试规则
- 查看设备属性：
~~~
udevadm info --attribute-walk /dev/ttyUSB0
# --attribute-walk是向上遍历父设备的所有udev属性
# /dev/ttyUSB0你要查询的设备节点
~~~
- 监视设备事件
~~~
udevadm monitor --kernel --property
# --kernel 表示监视内核事件
# --property 表示附加监视的事件的属性
~~~
- 测试规则
~~~
udevadm test /sys/class/tty/ttyUSB0
~~~
