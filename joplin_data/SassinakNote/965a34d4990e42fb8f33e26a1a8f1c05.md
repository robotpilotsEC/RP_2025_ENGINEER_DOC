# 二，项目初始化 

## 安装依赖
官方漏了一个插件，我们按照学长整理好的依赖来配置
~~~
sudo apt install --no-install-recommends git cmake ninja-build gperf ccache dfu-util device-tree-compiler wget \
    python3-dev python3-venv python3-tk python-is-python3 xz-utils file make gcc g++ gdb-multiarch \
    gcc-multilib g++-multilib libsdl2-dev libmagic1 openocd -y
~~~

- 此外**必须注意**，如果需要使用` nrf connect`插件，就会使用ncs工具链(具有dts跳转功能)。在`ubuntu22.04`版本下(`ubuntu24`没这个问题)，apt包管理器**默认安装**的是`python3.10`，而ncs工具链在构建项目的时候会**明确指明**python版本依赖为3.12.
***

## 兼容性安装python3.12
**如果你不需要dts跳转功能或者，你是24版本的ubuntu，可以跳过这一步**
~~~
sudo apt update
sudo apt install software-properties-common
sudo add-apt-repository ppa:deadsnakes/ppa
sudo apt update
~~~
- 安装后必须查看一下自己的**版本**和**位置**
~~~
which python3.12
python3.12 --version
~~~
- `python3.12`开始不再支持'`distutils'`模块，没法直接 `python3.12 -m pip`安装pip管理器
- 我们**剑走偏锋**
~~~
python3.12 -m ensurepip --upgrade
~~~
- 执行后会有警告
~~~
sassinak@sassinak:~$ python3.12 -m ensurepip --upgrade
Defaulting to user installation because normal site-packages is not writeable
Looking in links: /tmp/tmp4qk3qvo_
Requirement already satisfied: pip in /usr/lib/python3/dist-packages (22.0.2)
Processing /tmp/tmp4qk3qvo_/pip-25.0.1-py3-none-any.whl
Installing collected packages: pip
  WARNING: The scripts pip3 and pip3.12 are installed in '/home/sassinak/.local/bin' which is not on PATH.
  Consider adding this directory to PATH or, if you prefer to suppress this warning, use --no-warn-script-location.
~~~

- 这个警告是指，这个pip3.12已经安装了，但是没有加入环境变量
- 手动加入一下就好了
~~~
echo 'export PATH=$HOME/.local/bin:$PATH' >> ~/.bashrc
source ~/.bashrc
~~~
- 同样的，安装后记得检查
~~~
sassinak@sassinak:~$ which pip3.12
/home/sassinak/.local/bin/pip3.12
~~~
- 至此我们可以安装`ninja`了
~~~
python3.12 -m pip install --user ninja
~~~
- 同样的检查路径和版本
~~~
sassinak@sassinak:~$ python3.12 -m ninja --version
1.13.0.git.kitware.jobserver-pipe-1
sassinak@sassinak:~$ python3.12 -c "import ninja; print(ninja.__file__)"
/home/sassinak/.local/lib/python3.12/site-packages/ninja/__init__.py

~~~

## 创建虚拟环境
~~~
python3 -m venv ~/zephyrproject/.venv
~~~
- `zephyrproject`可以是任意一个名字，通常我会把workspace下建立的 APP文件夹作为这个名字
- **注意**，使用这个命令产生的虚拟环境，默认调用的是ubuntu包管理器的python版本。我是`ubuntu22.04`，所以是`python3.10`

**建议使用`python3.12`创建虚拟环境**
~~~
python3.12 -m venv ~/zephyrproject/.venv
~~~
- 还是那句话，**位置路径自己改**

## 创建工作区并编写 `west.yml`
我个人更喜欢这样的工作区
~~~
Engineer-workspace
├── Engineer
│   ├── Application
│   ├── boards
│   ├── include
│   ├── lib
│   └── README.md
├── Engineer-manifest
│   ├── submanifests
│   └── west.yml
└── Engineer-sdk
    ├── module
    ├── modules
    └── zephyr
~~~
- 首先需要自己编写 `west.yml`文件

### west.yml 文件的基本格式
~~~
manifest:			#所有的manifest配置文件都是这个开头

  defaults:						
    remote: XXX                                    # 设置默认的remote，这样下面的project就可以不写remote字段

  remotes:                                                # 这里可以配置多个远程仓库 必须是复数                     
    - name: XXX                                      # 这个名字是为了方便后面项目配置时选择url路径
      url-base:                 # 注意这里并不是.git结尾,这里只是搜索路径的一部分，后面还需要跟项目名(Engineer)
    - name: Zephyr-RTOS
      url-base: https://github.com/zephyrproject-rtos     # 这里写多一个官方的项目主要是方便后续项目的

  projects:
    - name: Engineer
      description: this is a test project,just to validate my study
      revision: main                                      # 必须有个revision字段，因为west默认查找的分支是master，而github新建的仓库默认分支是main
      path: XXX
    - name: XXXX
      remote: XXXX                                  # 项目内的remote必须是单数的
      revision: main
      path: XXXXX                                   
      import:							# 指示需要的模块，其他模块没写的不会被下载
        path-prefix: XXXX				# 这个是路径的前置名字
        name-allowlist: 
        
  self:									# 递归依赖树
    path: Engineer-manifest
    import: submanifests

~~~

- 必须注意 `remote`在单个项目中**是单数**，多个 url 是复数
- `projects`: 如果包含多个项目也**必须是复数**
- **推荐**先创建好项目的架构（文件夹）再初始化

### 初始化 west init
初始化前先查看当前初始化的`manifest`文件是不是你编写的
>west config -l

确定文件路径是对的，就可以 `west init` `west update`
