# node.hpp详解

~~~
class Node : public std::enable_shared_from_this<Node>
~~~

- 这里使用了`<memory>`头文件里面的模板类，配合`std::shard_ptr`智能指针使用。
- 这个模板类可以获取一个**指向自己**的智能指针。
- 这个执政和外部指向该对象的智能指针**共享引用计数**

值得注意的是：

- 这个对象必须在最初就被`std::shard_ptr`管理。

***
`RCLCPP_SMART_PTR_DEFINITIONS(Node)`
这是一个宏定义，为指定的类定义一组**智能指针类型的别名**

`RCLCPP_PUBLIC `
也是一个宏，常定义在动态库API的类或者函数前。

- 它修饰类，函数使其可以**被外部访问**

以下是它在不同平台的展开：
1. Linux / macOS （GCC/Clang）
`__attribute__ ((visibility ("default")))`
让被修饰的类/函数在编译成共享库（.so）时符号可见，外部能链接到。
`__attribute__ ((visibility ("hidden")))`
符号隐藏，只能在库内部用。
2. Windows （MSVC）
`__declspec(dllexport)`
编译库时，导出符号，外部能用。
`__declspec(dllimport)`
链接到库时，引用外部符号。
4. GNU工具链下的 Windows
`__attribute__ ((dllexport))`
功能和 MSVC 的 `__declspec(dllexport)` 一样。
5. 没有特殊支持的编译器
宏会展开为空，不做特殊处理。

## 使用场景

~~~
class RCLCPP_PUBLIC Node {
    // ...
};
~~~

~~~
 RCLCPP_PUBLIC //"rclcpp/visibility_control.hpp"
  explicit Node( //禁止隐式转换的构造函数。
    const std::string & node_name,
    const NodeOptions & options = NodeOptions());

  /// Create a new node with the specified name.
  /**
   * \param[in] node_name Name of the node.
   * \param[in] namespace_ Namespace of the node.
   * \param[in] options Additional options to control creation of the node.
   */
  RCLCPP_PUBLIC
  explicit Node(
    const std::string & node_name,
    const std::string & namespace_,
    const NodeOptions & options = NodeOptions());

  RCLCPP_PUBLIC
  virtual ~Node();
~~~
- 这里有两种`Node()`构造函数，支持多加一个命名空间。
- 这里运用了重载


***
~~~
RCLCPP_PUBLIC
rclcpp::callback_group::CallbackGroup::SharedPtr
create_callback_group(rclcpp::callback_group::CallbackGroupType group_type);
~~~
- 定义了一个智能指针，指向了`CallbackGroup `对象，但是没有定义对象本身。
- `CallbackGroupType` 这是ros2中的`枚举类型` **区分回调组的执行模式**。（互斥型`MutuallyExclusive`，可重入型`Reentrant`）

  ***
  ~~~
  RCLCPP_PUBLIC
  const std::vector<rclcpp::callback_group::CallbackGroup::WeakPtr> &
  get_callback_groups() const;
  ~~~

- 这是一个`const`成员函数。返回类型是**弱智能指针集合的常引用**。
- `WeakPtr`不增加引用次数。
